05conceitos
01

DOM

✓ entendido

O navegador lê o HTML e monta uma árvore de objetos em memória. Cada tag vira um nó. JavaScript conversa com essa árvore — não com o arquivo.

💡

Analogia: o HTML é a planta da casa. O DOM é a casa já construída. Você mexe na casa (DOM), não na planta (HTML). 

const h = document.createElement("h3");
h.textContent = "Novo título";
document.body.append(h);
⚠️

Armadilha: alterar o DOM muda a tela imediatamente. Não existe "salvar" — é por isso que é tão poderoso e tão fácil de errar.

02

API

✓ entendido

Uma API é um contrato: "mande um pedido para esta URL, no formato X, e te devolvo no formato Y". O servidor não sabe quem você é — só responde o que foi combinado.

💡

Analogia: é como garçom de restaurante. Você não entra na cozinha — faz o pedido pelo cardápio (a URL) e recebe o prato pronto (a resposta). 

GET /api/usuarios
GET /api/usuarios?scenario=error
⚠️

Armadilha: a mesma URL pode responder de formas diferentes (200 com lista, 500 com erro). Seu código precisa tratar todos os casos.

Verifique seu entendimento

O que uma API define?

03

Promise

✓ entendido

Uma Promise é um recibo de valor futuro. Você recebe o recibo agora, o valor depois. Só pode terminar de duas formas: resolvida (chegou) ou rejeitada (falhou).

💡

Analogia: o buzzer de restaurante. Você faz o pedido e recebe um aparelho. Não tem comida ainda — mas tem a garantia de que vai chegar. 

const p = fetch("/api/usuarios");  // Promise
const res = await p;                // Response
const dados = await res.json();     // array
⚠️

Armadilha: esquecer o await é o erro #1. Sem ele, você fica com a Promise, não com o valor.

Verifique seu entendimento

O que fetch(url) retorna imediatamente?

04

Fetch e HTTP

✓ entendido

fetch() é a função que faz requisições. Você envia uma URL e recebe uma Response com status, cabeçalhos e corpo. HTTP é o protocolo — o "idioma" que os dois lados falam.

💡

Analogia: mandar carta registrada. Você escreve um endereço (URL), e recebe de volta um envelope com status (200, 404, 500) e conteúdo. 

const res = await fetch(url);
if (!res.ok) throw new Error(`HTTP ${res.status}`);
const dados = await res.json();
⚠️

Armadilha: fetch NÃO rejeita a Promise em 404 ou 500. Ele só falha se a rede cair. Você precisa checar res.ok manualmente.

Verifique seu entendimento

O servidor responde com status 500. O que fetch faz?

05

JSON

✓ entendido

JSON é um formato de texto para estruturar dados. Parece objeto JavaScript, mas é uma string. Precisa de JSON.parse para virar objeto de verdade.

💡

Analogia: receita escrita à mão. Você precisa ler e interpretar antes de cozinhar. O JSON.parse é o ato de interpretar. 

const txt = '{"nome":"Ana"}';
const obj = JSON.parse(txt);
console.log(obj.nome);  // "Ana"
⚠️

Armadilha: status 200 OK não garante JSON válido. O servidor pode responder texto puro — e aí .json() rejeita com SyntaxError.

Verifique seu entendimento

Como um corpo JSON vindo da API se torna objeto em JavaScript?
